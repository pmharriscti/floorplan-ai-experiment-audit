# bim_bridge_v0: Downstream IFC Bridge

> The meaningful result today is not ‘we generated a 3D picture.’ It is ‘we can turn reviewed prediction-derived geometry into identifiable IFC building elements, preserve uncertainty, and inspect the result.’ That is a concrete step toward the PM’s BIM goal—and it creates a stable destination for the ML improvements that follow.

This statement is the acceptance principle of the experiment. A render, an anonymous mesh, a syntactically
valid IFC, or a synthetic-only example does not establish the prediction-to-BIM bridge.

**This is a downstream integration experiment. It trains and evaluates no model, and it is not comparable
with the segmentation experiments in this repository. Its pixel-metric scoreboard columns are `UNKNOWN`.**

## Outcome

| Milestone | Status |
| --- | --- |
| Technical exporter, shown on synthetic geometry | **PASS** |
| Reviewed prediction bridge | **PARTIAL**: not demonstrated. Gates not passed: G2, G6 |
| Downstream application or viewer acceptance | **NOT_RUN** |

**The reviewed-prediction IFC milestone remains partial. It was not demonstrated.** The technical chain from
saved predictions to inspectable IFC objects works on unreviewed candidates. Nobody has reviewed the
geometry, the drawing has no scale evidence, and nobody has opened the file in a viewer.

These three milestones are different results. A pass on one is not a pass on another.

## Tested Question

Can a small, explicitly reviewed subset of current floor-plan predictions become individually identifiable IFC walls and a hosted opening, with inspectable dimensions, provenance, uncertainty, and reproducible validation?

```
frozen prediction artifacts -> traceable candidate geometry -> recorded review/corrections
    -> building_model.json -> IFC objects -> validation and inspection
```

## Verified Input

One validation sample of the Phase 5 hierarchical run, `high_quality_architectural/333`. The input is the run's saved
prediction file, a thresholded `uint8` bitmask PNG. It is not a probability map and not a colour overlay.

- Bit 0 is `structural_wall` and bit 5 is `door_opening`. The layout was verified against the upstream
  `masks/README.md` and against the writer `_save_prediction_masks` in the upstream source.
- Thresholds are inherited from experiment 09: `structural_wall` 0.05, `door_opening` 0.95. This experiment selects no threshold.
- The source image hash equals the upstream manifest. The checkpoint hash `c281b31974e1...` equals the one in audit entry 09.
- No inference was run. No annotation SVG and no ground-truth mask was read.

The input was chosen because its lineage is complete and because it has a `door_opening` head, so the
aperture comes from the model. It was not chosen for its metrics.

## Verified Configuration

- Geometry extraction reuses the existing floorplan-synth vectorizer, unmodified, on the decoded predicted
  wall mask. It produced 14 candidate walls; 4 were selected, with one predicted aperture.
- Walls are straight, vertical and of constant thickness. The wall axis is the centreline.
- Coordinates map from image pixels through the recorded letterbox and the region of interest to metres,
  with the y axis flipped once. Units are metres.
- IFC4, written with IfcOpenShell 0.8.5. IFC4 is a prototype choice: no receiving application is documented,
  and target compatibility is `UNVERIFIED`.
- Property sets `AutoAutoCAD_Provenance` and `AutoAutoCAD_ModelProvenance` are application-specific.
- No materials, fire ratings, load-bearing status, equipment data or inspection status are written.

## Manual Inputs, Edits and Assumptions

- **Human inputs: none.** No reviewer, review date or approval exists, and none was invented.
- **Agent inputs.** An AI assistant chose the wall selection and read the area label `1 H+K+S 39.5 M2` from
  the source image. Both are recorded in the run configuration. An agent input is not a review.
- **One edit by an automated rule.** The vectorizer proposed a thickness of 40 px for `wall_012`, which is
  its maximum clamp. The predicted mask measures 4 px. The bridge replaced the value, recorded the edit with
  its before and after values, and kept the original.
- **Assumed for preview:** every wall height, wall base elevation, storey elevation, aperture height and
  aperture bottom elevation, from the profile `preview_vertical_defaults_v0`.
- **Plan scale.** The drawing has no dimension string and no scale bar. The scale is an estimate from the
  apartment area label: `0.010720` m per source pixel. It is not evidence, it is not
  human-confirmed, and it supports no dimensional claim.
- **Semantic confidence is null for every object.** The input is a thresholded mask. No score was derived
  from pixels, IoU, F1 or a successful export, and no overall confidence is computed.

## Interpretation

Outcome label `partial_downstream_integration`. The exporter works, and the chain from a saved prediction to individually
identifiable, property-carrying IFC objects works end to end. That is a technical result on unreviewed
candidates. It is not the reviewed-prediction milestone.

The experiment also found a defect in reused code. The vectorizer's thickness is unreliable for thin
partitions, and the bridge now measures thickness on the predicted mask.

## Missing Evidence and Non-Claims

- No new wall IoU, no segmentation improvement, no training comparison and no broad reliability claim.
- No dimensional accuracy. No reference geometry was used, so accuracy is unknown. It is not zero error.
- No human review, no evidenced plan scale, no viewer inspection, no target application.
- No semantic confidence, because upstream saved no probability maps.
- One region of one validation sample. Nothing here generalises.
- Wall joins are not resolved, so summed wall volumes are not a quantity take-off.
- Not fit for engineering, inspection or construction use.
